The honest part

Challenges and limitations

AI coding isn't cheap

Heavy AI-assisted development adds up fast, so I spread the work across several coding agents and used the Git repository to keep them in step: a branch per task, pull requests as the hand-off, and written rules every agent follows.

Home hardware isn't enterprise grade

A home router and a Raspberry Pi have little to spare and little to tune, so I control how resources get used: checks are spaced out, heavy tests never overlap, and only one trace runs at a time.

Cloud is expensive

I know AWS and GCP well, but I wanted my costs as low as possible, ideally free. So I moved to Oracle Cloud's free tier and kept the server small.

Testing without a fleet of devices

A separate non-production environment is a must, which means a separate Pi for each. I didn't want to buy more hardware until one proved it could work for this project. It has. Until then, virtual Pis cover most of it, but they can't reproduce real Wi-Fi radios or a real home network.

Roadmap

Phase 2.0: an AI operations team, someday

I'd love to build AI agents that read the logs, find the root cause of an outage, then restore service, fix the problem and even contact the ISP. It's a plan, not a build, and it costs real money, so it isn't practical yet.
